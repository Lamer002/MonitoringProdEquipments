# Мониторинг производственного оборудования

Это мой проект на C++ и Qt. В нём я сделал небольшую систему наблюдения за виртуальными станками: можно добавить оборудование, посмотреть его состояние и увидеть, как меняются показания во время работы.

Сразу уточню: программа не подключается к настоящим станкам. Температура, обороты и нагрузка моделируются программно. Мне хотелось сначала разобраться с логикой мониторинга, событиями и интерфейсом, а уже потом думать о работе с реальным оборудованием.

## Что происходит в программе

В главном окне отображается список станков. Для каждого видны его состояние и текущие показатели. Можно открыть отдельное окно с подробной информацией, добавить новый станок или удалить существующий.

Эмулятор обновляет данные примерно раз в секунду. Если температура становится слишком высокой, появляется предупреждение. При критическом перегреве предусмотрена аварийная остановка. События записываются в SQLite, и их можно посмотреть в журнале.

## Как устроен код

`MainWindow` отвечает за интерфейс и действия пользователя. `EmulatorManager` управляет эмуляцией, обновляет данные и обрабатывает события. `Machine` хранит состояние отдельного станка. Для обмена информацией между компонентами используются сигналы и слоты Qt.

Журнал хранится в файле `LogsMachine.db` в стандартной папке данных приложения. Её расположение зависит от операционной системы.

## Технологии

Основная логика написана на C++17. Для интерфейса использованы Qt Widgets, для хранения журнала — SQLite. Сборка настроена через CMake. В проекте также есть проверки через CTest и конфигурация GitHub Actions.

## Как собрать

Понадобятся CMake 3.16 или новее, компилятор с поддержкой C++17, Qt 5 или Qt 6 с модулями Widgets и SQL, а также драйвер SQLite для Qt.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

После сборки запустите `MonitoringProdEquipment` из каталога сборки. Для Visual Studio и других многоконфигурационных генераторов можно отдельно выбрать Release:

```bash
cmake --build build --config Release
```

На другом компьютере для запуска могут понадобиться библиотеки Qt и плагин SQLite.

## Проверка

Для сборки и запуска имеющихся тестов используйте:

```bash
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Сейчас тестами проверяется прежде всего модель станка: начальные значения, обработка недопустимых параметров, счётчики и сброс состояния. Интерфейс и взаимодействие с базой данных пока не покрыты полноценными автоматическими проверками.

В `.github/workflows/build.yml` настроена сборка и запуск тестов в Linux при изменениях в репозитории. Статус конкретного запуска можно посмотреть во вкладке Actions.

## Зачем я делал этот проект

Мне интересна разработка программ, которые взаимодействуют с оборудованием. Здесь я хотел потренироваться не только в C++ и Qt, но и в разделении логики, интерфейса и хранения данных. В дальнейшем проект можно развивать в сторону мониторинга настоящих устройств, но сейчас это именно эмулятор.
